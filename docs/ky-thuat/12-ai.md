# AI Report

## 1. Mục tiêu

Tạo nhận định kỹ thuật bằng tiếng Việt, dựa trên dữ liệu đã chuẩn hóa, có evidence.
AI **không sửa score/ranking**.

## 2. Prompt v2

- Trả lời hoàn toàn bằng tiếng Việt.
- Summary 3–4 câu, có ít nhất 2 chỉ số kèm giá trị.
- Mỗi điểm mạnh/điểm cần lưu ý có chỉ số + giá trị + ý nghĩa/ngưỡng.
- Nêu trade-off và giới hạn dữ liệu.
- Không đưa lời khuyên đầu tư.

## 3. Luồng model

```text
primary → fallback → template
```

- Primary lỗi/JSON invalid → fallback.
- Fallback lỗi → template tất định.
- Template v2 cũng phân tích theo số liệu.

## 4. Schema

Các field bắt buộc:

- `summary`
- `strengths`
- `weaknesses`
- `risk_flags`
- `missing_data`
- `evidence_ids`

`evidence_ids` phải nằm trong allowlist.

## 5. Budget và cooldown

- Cooldown 24 giờ/trader.
- Budget ngày/tháng cấu hình trong Settings.
- Dedupe theo hash dữ liệu đầu vào.

## 6. Giới hạn

- Model có thể trả sai/thiếu field → fallback.
- Không đảm bảo phát hiện mọi rủi ro.
- Không thay thế đọc số liệu gốc.

## 7. AI Agent chat (Phase 6b)

- Kiến trúc: `POST /agent/chat` (SSE) → `services/agent/orchestrator.py`
  (planner + tool loop tối đa 8 bước) → tools → verifier → lưu DB.
- Module: `schema.py` (ToolResult/AgentAnswer/SSE), `model_client.py`
  (OpenRouter native tool calling + JSON protocol fallback, primary → fallback 1×),
  `tools.py` (registry), `verifier.py` (số phải có evidence, chặn lời khuyên đầu tư).
- Reasoning: dùng chung `build_reasoning()` — `AI_REASONING_EFFORT=auto`
  (GLM 5.3 Flash `effort: low`, model khác `enabled: false`).
- Chỉ admin (`require_admin`); rate limit 20/phút; budget `ai_usage.feature='agent'`.
- Web search Tavily: cache Redis 24h theo hash query, timeout 10s; tắt khi thiếu key; snippet là untrusted data.

## 8. Verifier và answer contract (Phase 6b)

- Mọi số trong câu trả lời phải có trong facts (evidence ledger), kèm đơn vị đúng (%/USDT/x).
- Mã trader nhắc tới phải nằm trong `row_ids` của tool.
- Lời khuyên đầu tư → gắn tuyên bố miễn trừ + warning.
- Contract: `answer/facts/citations/assumptions/missing_data + confidence` (high/medium/low từ facts/warnings).
- Citation UI nhóm theo nguồn (Dữ liệu/Tài liệu/Web) + ngày `as_of`.

## 8b. Dữ liệu agent nhận (kế hoạch 04)

- `get_trader_profile(detail=full|summary)` trả 4 khung × 8 chỉ số
  (roi, pnl, mdd, sharpe, copier_pnl, win_rate_order, win_orders, total_orders),
  38 `derived`, 10 `profile`, `breakdown`, `flags`, `risk_events`; evidence cho từng khung
  (`roi_7d`…`win_rate_180d`) và derived chính.
- `search_traders(include=metrics|full)` trả thêm `windows` + evidence 7D/30D/180D.
- Observation gửi model là JSON compact; vượt `AGENT_OBSERVATION_CHARS=8000` thì cắt theo
  row kèm `truncated/omitted_rows/hint` (không cắt giữa object).
- Verifier chấp nhận số đã làm tròn (dung sai 0.005) và bỏ qua nhãn khung `7D/30D/90D/180D`.
- Độ mới dữ liệu: `services/freshness.py` phân 4 mức `ok ≤150'`, `stale ≤1440'`, `very_stale`,
  `unknown`. Agent phát `warning` khi stale/very_stale và thêm `freshness_unknown` vào
  `missing_data`; ngưỡng dùng chung với chip trên UI.
- `as_of` của số liệu published = `metrics.provenance.performance_at` (mốc thu thập);
  `computed_at` là mốc tính lại và luôn trả riêng, không dùng thay `as_of`.- Eval 15 case phân tích/đánh giá: `tests/test_agent_eval_analysis.py`.

## 8c. Câu hỏi khái niệm & chống lặp tool

- `knowledge_base.py`: 14 concept tất định (tier A/B/C/bị loại, Sharpe, MDD, WinRate,
  risk_score, mức điểm, bảng xếp hạng, copier, khung thời gian, pre_score/confidence,
  profit factor/phí, freshness, đòn bẩy). `search_knowledge` luôn ghép concept vào kết quả,
  kể cả khi full-text index rỗng → câu hỏi khái niệm không cần index vẫn trả lời được.
- Index RAG: backend mount `./docs:/app/docs:ro`; `repo_root()` tự dò thư mục chứa `docs/`
  nên `python -m app.knowledge_cli index` chạy được trong container (156 file → 964 chunk).
- Chống lặp: mỗi cặp `(tool, arguments)` chỉ thực thi 1 lần; lặp lại sinh `warning` và nhắc
  model dùng kết quả cũ. Khi lặp ≥ 2 lần hoặc ở bước cuối, gọi model **không kèm tool** để
  buộc trả lời; nếu vẫn rỗng thì dùng template từ evidence, cuối cùng là thông báo thiếu dữ liệu.
  Không bao giờ kết thúc bằng câu trả lời rỗng.
- Test: `tests/test_agent_knowledge_base.py` (14 câu khái niệm) và `tests/test_agent_loop_guard.py`.

## 8d. Copy plan theo vốn (Phase 6e)

- Tool `build_copy_plan` (`services/agent/copy_plan_tool.py`) → `services/copy_plan/`:
  `limits.py` (biên form Binance + version), `policy.py` (safe/balanced/aggressive/custom),
  `planner.py` (hàm thuần), `validate.py` (biên/evidence/nhất quán), `data.py` (adapter DB).
- `AgentAnswer.copy_plan` lưu JSONB vào `agent_messages.copy_plan` + `copy_plan_version`;
  SSE `done` và `GET /agent/sessions/{id}` trả kèm.
- Quy tắc: thiếu dữ liệu → `null` + `status=missing`, không đổi thành 0; mode chỉ tự chọn
  khi đúng một mode hợp lệ; cả hai hợp lệ → `needs_choice`; `low_liquidity` null ở MVP.
- Model lỗi nhưng đã có plan → `template_from_copy_plan` trả cấu hình tất định, không bịa.
- Eval: `tests/test_agent_copy_plan_flow.py`, `test_agent_copy_plan.py`,
  `test_copy_plan_planner.py`, `test_copy_plan_data.py`, `test_copy_plan_limits.py`.

## 9. Hardening: eval, retention, fallback (Phase 6b)

- Bộ eval 50 câu (`test_agent_eval.py`): top 10, vốn, code, web, multi-turn, unknown, SQL attack, advice.
- Retention session 90 ngày (`agent_retention.py`); cascade xóa message/tool/citation.
- Model chính + phụ đều lỗi mà đã có dữ liệu tool → template tóm tắt từ evidence; chưa có dữ liệu → event lỗi.
- Feedback 👍/👎 lưu `agent_feedback`.
- Cost/latency log: `ai_usage.feature='agent'` + `duration_ms` trong `agent_tool_calls`.
- Lưu `agent_sessions/messages/tool_calls/citations/feedback`.
- SSE events: `token/tool_call/tool_result/citation/warning/done/error`.
